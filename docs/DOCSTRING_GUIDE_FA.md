# قرارداد Docstring برای PyDara

در نسخهٔ `0.6.0a3` تمام تعاریف تابع، متد و کلاسِ موجود در `src/pydara` دارای Docstring هستند. برای مستندات آینده از Docstringهای درون کد به‌عنوان منبع آغازین استفاده کنید و مشخصات رسمی و محدودیت‌های API را با `docs/API_REFERENCE.md` تطبیق دهید.

- ساختار پیشنهادی: یک جملهٔ خلاصه، سپس بخش‌های `Args`، `Returns`، `Raises` و در صورت نیاز `Notes` و `Examples`، با قالب Google-style.
- `Args`: نام پارامتر و نوع و معنای آن. نوع باید با annotation و امضای واقعی سازگار باشد.
- `Returns`: نوع و معنی خروجی؛ برای DataFrame ترتیب و نوع ستون‌ها را از مرجع API بررسی کنید.
- `Raises`: فقط خطاهایی که کد یا قرارداد API پشتیبانی می‌کند؛ خطاهای داخلی پیاده‌سازی را بی‌دلیل به قرارداد عمومی تبدیل نکنید.
- تفاوت دادهٔ تازه، کش و حالت آفلاین و همچنین `on_multiple` و `on_conflict` باید در مستندات عمومی محفوظ بماند.
- توضیحات توابع کمکی داخلی از نظر جزئیات محدودند و جایگزین راهنمای آموزشی و مثال‌های قابل اجرا نیستند.
- تست `tests/test_docstrings.py` پوشش وجود Docstring را کنترل می‌کند؛ صحت معنایی همهٔ متن‌ها را خودکار تضمین نمی‌کند.
- داده‌های نمونه یا ساختگی، تصدیق داده‌های زنده نیستند؛ ماژول‌های آینده مستند نمی‌شوند مگر پس از پیاده‌سازی.

## به‌روزرسانی 0.6.0a7

- برای توابع اصلی `tse.instrument`، `tse.history` و `tse.price` راهنمای تفصیلی شامل `Args`، `Returns`، `Raises`، `Notes` و `Examples` اضافه شد.
- در توابع عمومی دیگرِ facade و متدهای متناظر Client/AsyncClient، نوع ورودی (در صورت وجود annotation)، مقادیر پیش‌فرض و نکته‌های رفتاری در Docstring آمده است.
- «نوع ورودی» و «مقادیر مجاز» یکسان نیستند: هر نوع یا گزینه‌ای که در Signature درج نشده، لزوماً مجاز نیست؛ در صورت تردید کد اعتبارسنجی منبع ملاک است.
- `help(tse.price)` و در Jupyter دستور `tse.price?` راهنمای درون کد را نشان می‌دهند. مرجع تولیدی `docs/API_REFERENCE.md` نیز همین Docstringها را منعکس می‌کند.

### خروجی یک‌واژه‌ای `clients()`

تابع `tse.traders()` جدول یکپارچهٔ حقیقی و حقوقی ارائه می‌دهد. برای نام‌گذاری ستون‌ها،
`ins_code` در خروجی آن `inscode` است. پیشوند `i` (مانند `ibuyvolume`) حقیقی،
و پیشوند `l` (مانند `lbuyvolume`) حقوقی است؛ پیشوندها در راهنمای تابع توضیح داده شده‌اند.
دادهٔ `DDD` با حقیقی/حقوقی ادغام نشده است. نام ستون‌های داخلی و کش تغییر نکرده‌اند.
